# CRONOS RESTORE — pendências e prioridades

1. **Integrações reais do Studio — prioridade alta.** A captura enviada pelo usuário mostra Gemini e Mistral em HTTP 429, OpenAI/OpenRouter em HTTP 401 e revisão de código recusada. São respostas de conta/cota e validação, não prova de que a troca de IA não foi executada. O Studio mantém o pedido, a versão e as tentativas. É preciso testar com pelo menos um provedor de código cuja chave, modelo e cota estejam válidos; nenhuma chave foi fornecida a este ambiente. Não se pode declarar uma pizzaria gerada por IA real aqui.
2. **Voz real no Windows — prioridade alta.** O worklet e a API passaram com amostras sintéticas, mas captação, permissão do WebView2, sensibilidade de VAD, ruído, Fish ASR e Fish TTS no notebook não puderam ser observados. O modo de ditado longo reúne segmentos no campo; falar por horas em uma única requisição não é suportado. Cada gravação tem limite explícito de três minutos, e a entrada de texto tem limite de 200 mil caracteres.
3. **Mensagens de texto acima do contexto do modelo — prioridade alta.** A API aceita até 200 mil caracteres e preserva o texto enviado, mas o contexto e os limites reais variam por provedor. `Engine.context` não resume uma entrada atual acima da janela; esse caso pode ser recusado externamente. A evolução correta exige conhecer as capacidades de cada modelo e preservar instruções ao dividir o texto, sem truncamento silencioso.
4. **Latência real e experiência da interface — prioridade média.** Medir p50/p95 por etapa no notebook; não há coleta desta máquina neste ambiente. Navegador/WebView2, áudio nativo e prévia do Studio precisam de teste manual Windows.
5. **Conclusão de projeto pelo Studio — prioridade alta após a integração.** O fluxo local e o empacotamento têm testes automatizados, mas o teste solicitado da pizzaria Forno Vivo com IA externa, imagens, carrinho e WhatsApp, seguido de uma barbearia, continua bloqueado por falta de provedor autenticado/cota e navegador Windows. Não substituir esse teste por um template ou mock.

O instalador público não leva `.env`, vault, modelos locais nem arquivos pessoais. Uma instalação nova exige configurar ou migrar credenciais privadas localmente, sem publicá-las no GitHub.
